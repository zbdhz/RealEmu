# Bluespec 稳定性与隐藏节点一致性：复审及后续修改报告

日期：2026-10-25，Asia/Shanghai。源码复审与证据采集跨 10 月 24—25 日。

## 1. 结论与实施顺序

后续修改应按以下顺序推进：**消除事件丢失造成的死锁 → 统一实际时钟与模型时基 → 确保配置真正下发且不丢失 → 修复 MAC 协议和 PHY 碰撞边界 → 验证隐藏节点的一致性。**

当前最严重的问题已经有真实 MAC+PHY 联接仿真证据：PHY 忙时仍取走 TX 请求，可能不产生本地发送；MAC 又依赖单周期 txEnd 和退避 done，寄存器访问或 FIFO 背压可能让它错过这些事件。前两类问题能产生板上看到的 `DCF=2、FIFO=10/10、PHY=0、CCA=0`。重启能清除状态，但不能消除触发条件。

另外两项已经由当前源码和本机实现工程确认：MAC 配置没有完整传播到退避/NAV 子模块；`run261021` 工程使用 250 MHz user_clk，源码按 200 cycles/µs 计时，并且该工程布线时序未收敛。这些问题会让“寄存器读回正确”“仿真能结束”“板上能收包”分别与实际配置、功能通过、性能可信脱节。

保持用户要求的最小修改范围：沿用现有状态机、LFSR、队列及 mode0 整包成功率判决，保留已有强信号重叠否决。优先补足握手、少量待处理状态和配置传播；不以新增分段 BER、完整干扰信号表或大规模 DCF 重构作为前提。

**实施进度（2026-10-25）：D01—D03 已按最小范围修改 MacCore/PhyCore，并通过24个自动化仿真用例及16节点生产顶层编译；详细代码改动、原版失败对照和验收记录见 [D01—D03 实施报告](bluespec-deadlock-fix-results-20261025.md)。T/C/M/P/V 的其余后续项尚未据此验收，未产生新的板测通过记录。本文缺陷位置与原始证据描述仍以第2节的1203808基线为准。**

**增量进度（2026-10-26）：T01/T02 与 C01/C02 已完成。10 个时基/配置用例及 250 cycles/µs 下原有 24 个回归全部通过；修改前工作树的 7 个针对性对照全部失败。16节点生产顶层在 xcu280-fsvh2892-2L-e 上完成250 MHz布局布线及布线后物理优化，WNS=+0.002ns、WHS=+0.009ns，TNS/THS均为0。具体改动、配置完成边界及证据见 [T/C 实施报告](bluespec-timing-config-fix-results-20261026.md)。本轮未烧写板卡，未据此宣称隐藏节点吞吐已与ns-3一致。**

## 3. 第一阶段：消除死锁

### D01：PHY 请求接受与 TX 启动必须可靠对应

**位置：** [PhyCore.bsv](../src/PhyCore.bsv)，`handleLowMacTxReqQ`，当前 162 行；`txValidReg`，115 行；`handlePhyState/PHY_IDLE`，325 行。

**已确认的因果链：**

1. `handleLowMacTxReqQ` 在 PHY 为 SYNC/RX/TX 时也能取走上游请求、回复 GenericResp、向信道入队。
2. 发送启动使用 `mkDReg(False)` 的 txValid，只存在一拍。
3. PHY 只有 IDLE 分支处理 txValid；忙状态没有保存请求。
4. 脉冲消失后，本地没有对应 TX_START/TX_END，但 MAC 已进入等待 CTS/ACK。
5. MAC 计时器依赖 TX_END 才从 0 启动，因此也不会超时。

已复现普通旁听 DATA 和“旁听中心发给另一节点的 CTS”两种触发：信道出口出现 1 个请求，本地 TX 开始/结束均为 0，5 ms 模型时间后仍为 DCF2、FIFO10、PHY 空闲。

**最小修改方案：** 保留原请求 FIFO 的背压能力，在能够保证接续到本地 TX 的条件下才消费请求。明确同周期 TX/RX 的优先级，使请求消费、参数保存、信道发布和本地启动组成一个可追踪的事务；忙时留在原 FIFO，或者仅增加一个确有需要的 pending 状态。

仅加 `state==PHY_IDLE` 不足：本拍已有 rxValid 时将进入 SYNC；本拍已有 txValid 时会启动旧请求，新请求的脉冲可能在下一拍落入 TX。正式补丁必须覆盖这些旧值窗口。信道发布与本地 TX 的固定流水差应有明确上界，不能出现信道已发送、本地永久未启动。

已有隔离 guard 实验能恢复正常重试，支持上述方向；但出现 G0010 调度冲突，不能原样作为生产补丁。guard 还必须包含请求非空条件，否则空规则可能抢占清理 txEnd。不能只添加 urgency 后忽略规则是否被永久压制。

**验收：** RX 先到、TX 先到、同周期到达、连续两个 TX、下游满后释放均无丢启动；每个接受的 TX 恰好有一次开始和结束；结束事件不会串到下一个请求。无应答时应重试并最终丢弃，之后继续处理队列。

### D02：txEnd 可靠捕获，应答计时独立于容易被阻塞的分支

**位置：** [MacCore.bsv](../src/MacCore.bsv)，`dcfRecvCtsAck` 660 行，计时启动 665/676 行，寄存器访问优先级 805 行；[PhyCore.bsv](../src/PhyCore.bsv) 的 442/323 行。

PHY 结束发送置 txEnd，下一拍 IDLE 清除。`handleMacRegAccess` 优先于 DCF 规则，普通读取也能阻止等待规则在这一拍执行。已复现一次读请求刚好覆盖 txEnd：本地开始/结束各 1 次，但 ACK/CTS 计数器始终为 0，读操作结束后也不能自行恢复。

**最小修改方案：** 在不会被寄存器访问或发送 FIFO 背压阻断的路径中捕获完成事件，保留到对应等待事务消费。可用少量 pending/等待阶段状态；需要按当前发送关联并清理旧事件，不能把上一帧的 txEnd 当成下一帧完成。

同时将时间推进从依赖队列 `.first/.enq` 或特定 RX 分支的规则中分离，明确计数器单一写入关系。连续监控不应让模型时间漏走；若使用独立时基和截止时间，需处理回绕；若保留计数器，需保证它持续推进并饱和或在超时后退出。不能只修“从 0 启动”，却继续因规则抢占漏计后续微秒。

开始应答等待的基准仍为实际 TX 完成。简单前移到 MAC 入队会把排队及本帧空口时间算入应答等待；增大 timeout 对始终为 0 的计数器无效。

**验收：** 在 TX_END 前一拍、同拍、后一拍读取或写入配置；叠加持续读监控和合法队列背压。均应捕获一次完成、按确定期限超时或接受合法响应，且不会重复启动计时。

### D03：退避完成保持到实际消费或取消

**位置：** [MacCore.bsv](../src/MacCore.bsv)，`mkCsmaCaBackOff` 的 isSendAllowReg 202 行、CSMA_DONE 315 行、IDLE 清除 224 行；消费者 `dcfWaitBackOff` 557 行。

CSMA_DONE 只产生一拍 done，随即回 IDLE。已复现普通寄存器读取抢掉消费周期：MAC 永久在 DCF1，内部 CSMA 已为 IDLE，done=0，完全没有发出请求。发送 FIFO 满也会阻止含 `.enq` 的消费规则执行，这是必须补测的背压分支。

**最小修改方案：** 将完成改成可握手的保持状态。优先停留 CSMA_DONE，直到 MAC 在同一个成功发送/状态切换动作中确认消费；明确取消时也可清除。复用现有状态，必要时增加一个 consume 方法或等价的局部握手。仅把 mkDReg 换成 mkReg 无效，因为 IDLE 分支仍主动清零。

完成后如果 PHY 已开始接收，需与 D01 的发送接受策略一致：不能无声丢请求，也不能无限保留一个已经失效的发送许可。普通竞争与 SIFS 响应分别规定继续等待、重新竞争或明确取消的处理条件。

**验收：** done 到达时暂停 MAC 消费 1/2/多拍，再恢复；发送队列满后排空；寄存器访问抢拍；取消后再启动。均只能消费一次，能够继续前进。

### 三项修复的共同通过条件

D01—D03 应作为第一个完整验收批次，避免新增 PHY 背压后立即暴露 done 丢失。测试允许在有界运行结束时仍处于正常退避，必须用“是否有进展、队头是否有界完成”判断，不能仅因最终 DCF 非 0 判死锁。

| 已有受控用例 | 原结果 | 修复后应满足 |
| --- | --- | --- |
| 无旁听、无应答基线 | 8 次 TX、8 次结束，已丢弃一个耗尽重试的队头 | 正常重试、有限次完成、继续处理下一项 |
| 旁听 DATA / 中心 CTS 与本机发送交错 | 1 个信道请求、0 次本地 TX，DCF2 | 不丢启动；旁听结束后恢复发送/失败处理 |
| txEnd 边界普通读取 | TX 1/1，计数器 0，DCF2 | 完成事件可靠捕获，等待有界 |
| done 边界普通读取 | 0 次 TX，DCF1、CSMA_IDLE | done 保留并最终消费 |
| 新增 FIFO 背压用例 | 尚未单独验收 | 释放背压后请求守恒、无永久等待 |

第一批优先在仿真中证明，不需要先增加全局 watchdog、复位协议或长期运行诊断框架。测试 watchdog 用于暴露失败，不用来掩盖 RTL 死锁。

## 4. 第二阶段：时钟与时间基准

### T01：以实际接入时钟统一 cycles/µs

**位置：** [Types.bsv](../src/Types.bsv) 的 US_CYCLES=200，245 行；[MacCore.bsv](../src/MacCore.bsv) 的 mkUsGen(200)，416 行；[PhyCore.bsv](../src/PhyCore.bsv) 的 clkFreq=200，84 行；各测试中的时间换算。

本次检查 `run261021/xdma_0_ex` 得到完整连接证据：XDMA IP 的 axisten_freq=250；`imports/xilinx_dma_pcie_ep.sv` 379 行将 axi_aclk 接到 user_clk，408 行将 RealEmu 的 CLK 接到同一 user_clk；布线报告 190 行显示 user_clk 为 4 ns、250 MHz。工程中的 100 MHz clk_wiz 不能用来解释 RealEmu 的实际接入频率。

若使用这份实现，当前计时会整体缩短为标称的 200/250=0.8：

| 标称值 | 当前所用周期 | 在 250 MHz 上的时间，未计固定流水 |
| --- | --- | --- |
| slot 9 µs | 1800 | 7.2 µs |
| SIFS 16 µs | 3200 | 12.8 µs |
| DIFS 34 µs | 6800 | 27.2 µs |
| timeout 300 µs | 60000 | 240 µs |
| DATA 180 µs | 36000 | 144 µs |

**最小修改方案：** 在公共类型/常量处保留一个权威 cycles/µs，MAC、PHY 和测试统一引用。当前工程优先按 250 配置，保留单时钟域，避免仅为沿用 200 引入 AXI 跨时钟域。若之后工程频率改变，构建配置必须同步生成/校验这个常量。

Bluesim 的默认物理周期为 10 ns，而旧模型用 200 cycles/µs。因此旧日志 `$time` 与模型时间存在两倍关系；改为 250 后关系还会改变。测试输出应同时明确周期数、模型 µs 和仿真器时间单位，不能直接把 `$time` 当模型微秒。也不能仅在汇总结果上乘一个系数后宣布硬件时序正确。

**BSIM 宏另有风险：** 源码定义 BSIM 会把 MAC/PHY 改成 1 cycle/µs，而 PHY 在 565 行写死 `timer==30` 才触发查表。此时 SYNC 总长仅 20 周期，正常路径达不到触发点。测试文件在 import 之后定义宏也不能可靠配置已编译的依赖包；ROM 的 BSIM 分支还涉及不同实现。首轮验收统一采用生产时基和独立构建目录，暂不启用这种加速语义。若保留加速仿真，以后需单独完成流水延迟与触发条件验证。

**验收：** 微秒 tick 精确每 C 周期产生；slot/SIFS/DIFS、各类帧 TX 长度符合统一公式，固定流水差单独说明；构建记录中的 C 与 Vivado user_clk 相符。板上指纹尚未核验，因此这里确认的是本机工程，不声称已经读回当前板上频率。

### T02：修复实现时序和 PHY 时长流水归属

`run261021` 的 routed timing summary 显示 WNS=-0.578 ns、TNS=-300.695 ns、1050 个 setup 失败端点。最差路径位于 `phyNodes_12_divider_fResponse` 到 `phyNodes_12_ccaTimerReg`，要求 4 ns、数据路径约 4.463 ns。该结果是实际实现缺陷，不能用逻辑仿真通过替代，也不能仅凭它断言已定位板上死锁。

**位置：** [PhyCore.bsv](../src/PhyCore.bsv)，`feed_operation/divideResult` 289—307 行，CCA 更新 236 行，以及 TX/SYNC/RX 的 timer 装载。

当前除法响应只有商和余数，未随结果携带 TX/RX 类型、原事件到达时间和强弱标志。TX/RX 同拍时 TX 优先，RX 时长请求可能未提交；结果返回时又使用当时的 state/rxPower 决定用途，连续长短帧可能发生归属错配。这些风险应先用定向输入验证。

**最小修改方案：** 继续复用现有除法器，仅为计算中事件保存必要标签，请求和标签同时接受、结果和标签同时消费；处理同拍 TX/RX，不能静默省略 RX 的能量占用。根据最新综合报告在除法结果、时长转换与 CCA 更新之间增加必要寄存级，优化比较/算术路径。新增流水延迟必须从原始到达/开始时刻扣除，不能从结果返回时重新计算整段空口时间。

同时去除依赖固定“提前 30 周期”的脆弱假设：明确一次查表请求对应哪个接收阶段、何时返回、何时允许结束。查表结果晚于计时终点时应有有界处理，不得让响应属于上一帧却完成下一帧。限定并检查当前实验合法长度和 MCS；现有 10-bit 商不能证明支持全部 16-bit 包长。

**验收：** 混合 MCS/长度、同拍 TX/RX、连续外来帧均不串时长；lookup 有明确次数和归属，PHY 状态不会永久等结果。最新 250 MHz 实现 setup/hold 通过，且没有依靠不真实的 false-path/multicycle 约束绕过活跃路径。

## 5. 第三阶段：配置下发与背压

### C01：MAC 配置必须到达实际消费者

**位置：** [MacCore.bsv](../src/MacCore.bsv)，805 行寄存器访问；`mkCsmaCaBackOff.putmaccfg`，362 行；`mkNav.putmaccfg`，175 行；[CsmaUtils.bsv](../src/CsmaUtils.bsv) 的 cfgReg。

AXI-Lite 写入只改变顶层 macCfgReg，当前没有调用 backOffFsm.putmaccfg，也没有调用 navctrl.putmaccfg。即便调用退避模块当前的 put，它也只继续传给随机窗口生成器，没有同步 NAV。

| 配置 | 当前实际消费者 | 当前问题 |
| --- | --- | --- |
| SLOT | mkSlotGen 直接引用顶层 macCfgReg | 可以影响 slot；运行中改值还需处理计数相位 |
| SIFS/DIFS/EIFS | 退避模块自己的 macCfgReg | 仍可能使用默认值，读回顶层新值不能证明生效 |
| CW_MIN/CW_MAX | 随机窗口模块自己的 cfgReg | 顶层写入未传播；当前 CW 和预取样本也需处理 |
| SIG_TIME/OFDM_SYMBOL/MAX_NUM/PHY_DELAY | NAV 自己的 macCfg | 写入未传播；这些字段也不能宣称会改变 PHY 硬编码时长 |
| TIMEOUT/RTS_THRESHOLD/RETRY_LIMIT/NAV_EN | 顶层 DCF/更新逻辑 | 会被直接读取，但需要明确配置切换边界 |

**最小修改方案：** 构造本次写入后的完整 cfg，同步交给顶层、退避、随机窗口和 NAV；复用已有 put 接口，补齐一条内部传播。可直接在配置写动作中传播，或使用小的 dirty/pending 状态。必须避免非阻塞更新导致传下去的仍为旧 cfg，也不能每拍广播造成状态机长期被配置规则阻断。

建议先规定测试/driver 在停止发流、排空后更新影响时序/CW 的配置；忙时的写入需要明确延后应用或返回错误，不能一帧前后使用两套参数。优先使用现有空闲状态和一个待应用状态，避免建立全局重配置协议。写响应和后续读回应能说明是已应用还是仅已缓存。

校验 slot 非 0、CW 指数范围及 min≤max、支持的 MCS/长度；不支持的 TXOP/filter 语义不能仅因可读写就宣传为已实现。CW 字段存指数，4 表示 CW=15，6 表示 CW=63，10 表示 CW=1023。是否从默认 6 改为 10，由受控对照参数决定，不与死锁补丁混做。

**验收：** 将 SIFS/DIFS/CWmin 设为显著不同于默认值，测实际响应间隔、首次随机样本及增窗边界；覆盖节点 0/3/4/15 的分组边界。读回与行为均正确，配置期间没有重现 D02/D03。

### C02：数据/配置路径在背压下不得静默丢事件

**位置：** [BsvTov_simple.bsv](../src/BsvTov_simple.bsv) 的 `forward_axi_to_bridge`，128 行；[CfgBridge.bsv](../src/CfgBridge.bsv) 的 txProcess/txBroadcast/txSend 及 PER 路径；[MacBridge.bsv](../src/MacBridge.bsv) 的上传/下传流水；[Arbitration.bsv](../src/Arbitration.bsv) 的广播流水。

顶层当前先 dequeue 输入，再向“未满”的 MAC/config/PER 队列复制。真正目标队列满时可能漏投，其他队列收到的无关副本不能补回它。CfgBridge/MacBridge/Arbiter 多处用 mkDReg 单拍 valid 连接有背压的 FIFO；消费规则不能执行时，valid 可能消失。这是事件守恒风险，需通过暂停下游的定向仿真确认每条边。

**最小修改方案：** 顶层先按现有 tag 解码，只在目标队列能接受时取走输入，直接复用现有三条队列。桥接处仅将失去保持能力的流水边界改成小 FIFO 或 ready/valid 保持；保留已有分组结构。配置广播可采用“所有目标都接受后再推进”的原子广播，避免无必要地新增每节点重放系统。仲裁公平性先测量，确认发生饿死时再做局部轮询修正。

本轮保留 DMA 二进制布局。若下游永久不消费，允许背压传播；验收条件应是有限背压解除后全部恢复，不能要求任意阻塞下无限接收而不丢包。

**验收：** 分别阻塞 MAC、单节点配置、PER 某一节点和主机接收，再释放；使用完整 ID 检查输入输出集合、字段、次数。不得“响应已接受，但配置实际没到”，也不得对同一事件重复广播。

### C03：配置完成语义与 AXI-Lite 协议

CfgBridge 在入口 dequeue 时就给 GenericResp，随后才传播到各节点；顶层又直接消费响应。因此当前内部响应主要表示入口已接收，不能证明 Channel/PER 的 BRAM 已更新。Channel/PHY 的写请求还使用 responseOnWrite=False。

首轮优先串行配置、停止发流，利用有界回归证明流水排空；需要主机可靠确认时，复用现有响应通路，在目标完成后归还响应，PER 广播等待全部目标完成。BRAM“写请求已接受”和“写已完成”的边界必须明确，必要时使用已有写响应。上层 DMA write 成功不等于这些内部响应已经返回；若要提供主机可读的完成边界，优先增加一个最小 fence/已应用计数入口，具体接口随 driver 一并定义。

[CfgAxiLite.bsv](../src/CfgAxiLite.bsv) 已分别缓存 AW/W，不应直接认定其必然要求两者同拍；应补 AW 先到、W 先到、B/R 背压和无效地址测试。目前 RegAccessReq 不携带 wStrb，控制器未使用写字节掩码，部分写不能当完整写静默处理。最小兼容方案可限定全字写、拒绝其他 strobe，再按真实 driver 需求决定是否扩展掩码。

**验收：** 连续距离/PER 更新之后立即验证实际接收功率/成功率；不会串入上一轮配置。全部 16 节点响应可核对，非法地址/不支持写法返回明确错误，有限总线背压释放后可继续访问。

## 6. 第四阶段：MAC 协议行为

### M01：CW 饱和、随机样本与退避冻结恢复

**位置：** [CsmaUtils.bsv](../src/CsmaUtils.bsv)，`mkExpBackoffGenerator`，104 行；incrCW，168 行；[MacCore.bsv](../src/MacCore.bsv) 的 CSMA_BACKOFF/SUSPEND 和 IFS 分支。

当前增窗使用 `cwExp > cwMax ? cwMax : cwExp+1`，相等时会越过上限一档；指数超出 LUT 支持范围还可能进入只使用 3-bit 随机数的 default。resultQ 在变更 CW 之前预取样本，incrCW/resetCW 不使旧样本失效，下一次退避可能继续使用旧窗口。历史审计在 CW0 reset 后前两次仍得到 13、8。

**最小修改方案：** 饱和比较修成覆盖相等边界；保留 LFSR，在 next.get 时按当前窗口取样，优先删掉预取 FIFO及失效问题。配置应用同时明确当前 CW 重置/夹取规则。保持节点随机性，不要求与 ns-3 随机序列逐位相同。

当前 SUSPEND 检测到空闲后直接回 BACKOFF，没有重新等待 DIFS/EIFS；slot 又来自自由运行全局相位，第一段可能不足完整 slot。复用已有 IFS 状态，增加必要的“恢复剩余退避”标志；恢复后不能重新抽随机数或覆盖原剩余值。校正局部 slot 相位，错误接收信息保持到对应 EIFS 决策。CTS/ACK 的 SIFS 响应不能被普通竞争的 NAV/退避错误阻挡；需要定向测量正在竞争时收到给自己的 RTS/DATA，补足必要的暂停/恢复。

**验收：** 首次 CW0 就是 0；连续增窗从不超过配置上限；CCA/NAV 忙时冻结、空闲后等待完整适用 IFS，再走完整 slot；剩余退避值保留。局部响应不会永久饿死，也不会破坏本节点原队头。

### M02：RTS/CTS/DATA Duration 与 NAV

**位置：** [CsmaUtils.bsv](../src/CsmaUtils.bsv) 的控制帧构造；[MacCore.bsv](../src/MacCore.bsv) 的 DATA Duration 611 行、CTS Duration 624 行、updateNAV 458 行、mkNav 145 行。

当前 DATA Duration=16+20+20=56 µs，但已有 +22bit 的 6M ACK 实际为 44 µs，应预约 60 µs。CTS 当前减去 SIFS+20+28=64，使用了 RTS 时长；应减去 SIFS+T_CTS=60。RTS 沿用输入描述符 duration，主机若填 0/单帧时长，预约不足。NAV 又只消费 RTS/CTS，并把短 Duration 强制抬到 119，连 0 都可能产生预约。

802.11a、20 MHz、5 GHz、控制速率 6M 的统一公式为：

```text
T(L,mcs) = 20 + 4 × ceil((8×L + 22) / NDBPS[mcs])，单位 µs
NDBPS = {24,36,48,72,96,144,192,216}
DATA Duration = SIFS + T_ACK
CTS  Duration = 2×SIFS + T_DATA + T_ACK
RTS  Duration = 3×SIFS + T_CTS + T_DATA + T_ACK
ACK  Duration = 0
```

例如 DATA=1062B、54M 时 T_DATA=180，RTS=52、CTS/ACK=44；对应 Duration 为 RTS316、CTS256、DATA60、ACK0。1064B 在这档也为 180，但其他长度/速率边界仍需逐项计算。

**最小修改方案：** 固定现有控制速率 6M，先将 ns-3 对照实际控制帧速率调成相同；DATA/CTS 使用正确剩余预约，NAV 取有效预约与已有剩余时间的较大者，加入符合条件的旁听 DATA，去掉任意 119 下限。Duration=0 不新增预约，也不清除已有预约。

为减少硬件算术，RTS 的完整预约首选由主机公共函数预计算后放入已有 duration 字段，setRtsFrame 继续复用。这要求同步修改真实 driver、独立 C 测试和 BSV 测试；输入 DATA 描述符的该字段语义须写清，不能继续直接拷原始 DATA 头 Duration。若必须保留旧字段语义，则仅在 MAC 内复用一个时长函数计算，二选一，不维护两套互相覆盖的计算。普通 CSMA 软复位不应顺带清空仍有效的 NAV。

**验收：** 直接核查发出的四类 Duration；旁听 CTS/DATA 后预约覆盖剩余交换；无关 Duration0 不产生 119；正常 ACK/CTS 按 SIFS 发送，NAV 不误挡本次交换响应。

### M03：应答匹配、无关流量和 timeout

当前 `dcfRecvCtsAck` 690/700 行只检查“目的地址是自己、类型是 CTS/ACK”，没有完整检查当前应等哪一种、来自哪个对端、对应哪个包。错误 ACK 可弹出当前队头，错误 CTS 可重复触发 DATA。旁听帧已改为只出队继续等待，这项已有修复应保留；但发给自己的意外帧仍立即消耗重试，且超时判断在 RX 非空分支的 else-if 中，持续无关流量可能拖延到期处理。

**最小修改方案：** 复用 nextTask、当前发送队头和控制帧复制的完整 cacheAddr，检查预期类型、src/dst、完整包 ID。不相关应答出队后继续等，超时判决独立于无关队列是否非空；定义合法响应与截止同拍的优先级。同一 MPDU 的不同重试可能共用 ID，仍需迟到响应测试；只有这些字段不足以解决实际用例时才添加尝试标记。

先保留 timeout=300 做稳定性回归。再测实际 SIFS、应答空口和流水差，确定有依据的整帧等待值。本机 ns-3 是“TX 结束后等待有效接收开始，接收开始后延至接收结束”；其初始 16+9+20=45 µs 不是等完整 ACK 的期限。RealEmu 现有 rxStart 来自进入 SYNC，不能直接等同 ns-3 的有效 PHY 头接收指示。

严格对齐此语义时，可复用现有计数器补少量“等有效头/等本次接收结束”阶段，并保持有界。完成之前，不能把 timeout 改为 45 就宣称一致；正常 6M ACK 连同 SIFS 已需 60 µs。保留整帧等待是规模更小的第一步，但仍要在对比中明确这一差异。

**验收：** 错类型/对端/包 ID 不完成当前队头；持续旁听不会阻止超时；无应答 retryLimit=6 对应初次+6 次重试，正常有限完成；应答截止边界不会双重完成或错误重传。

### M04：请求完成、接收交付与主机 ACK 语义

当前 MAC 成功 ACK 路径在 712 行给 highMacTxRespQ，多个最终丢弃路径只删除队头，不给同样的 GenericResp。Bridge 当前直接消费响应，不靠它阻塞推进，所以这不是已复现 DCF2 的直接根因，但接口不完整会使严格等待完成的调用者卡住。

**最小修改方案：** 所有最终完成出口恰好归还一次已有 GenericResp，核查队头删除和 FIFO count 的净变化；BACKOFF_STATE 改读实际 backOffFsm 状态，当前 macStaReg.backOffState 未动态更新，读到 0 不能证明实际退避空闲。先用仿真内部状态验证，诊断寄存器只补必要内容。

更关键的是：highMacRxReqQ 在收到 DATA 时产生，真正发送方收到 ACK 时仅产生 GenericResp。当前 realwmediumd 把硬件返回 status=1 作为单播成功并置上层 ACK 标志，这两种时刻语义不同。DATA 已到而 ACK 丢失时，硬件会重传并再次交付 DATA，可产生重复回报；不能仅据此判断 DMA 重复。

处理分两层：当前板测先将“唯一 DATA 到达”和“发送方 ACK 完成”分开解释，主机按完整 ID 去重；若要让上层 ACK 状态严格正确，需实现成功/失败 TX 完成通知，并保留独立 RX 交付。优先评估复用现有 MacEvent 宽度及字段区分事件种类，联合更新 BSV/driver 并定义兼容性。**仅补 GenericResp 并不能把 ACK 结果送到主机，也不能单独解决这一接口语义问题。** 此项应独立提交，不混进第一批死锁修复。

**验收：** 每个接受的上层请求恰好完成一次；并发入队/完成计数守恒；ACK 丢失时接收交付和发送成功不会混计；重试耗尽不会被报告成功。

## 7. 第五阶段：PHY 与 mode0 的边界修复

### P01：保留整包模型，记录外部强干扰的尾部

**位置：** [PhyCore.bsv](../src/PhyCore.bsv) 的 SYNC/RX collideReg、CCA timer 和接收入口。

当前已有 csThreash=128、SYNC/RX 强重叠标记和 CRC 否决，不能再按旧文档认定“完全没有碰撞处理”。但是它只跟踪当前锁定帧的碰撞：

```text
A: [0,176) µs
B: [100,276) µs
C: [200,376) µs
```

A/B 重叠使 A 失败，B 未成为当前接收对象。A 结束后 PHY 空闲，C 到达时 B 实际仍在空口，但没有新 B 到达事件触发 collide，C 可能错误成功。历史三帧审计确有此结果；当前源码仍存在同类缺口，修复前应以当前统一时基重新纳入回归。

**最小修改方案：** 对当前“过门限强信号任意重叠都否决”的二值规则，只需保存外部强 RX 信号的最晚结束时间，或等价的剩余时长。优先复用可区分的已有状态；CCA 混入本机 TX 时，新增一个独立外部强 RX 标量即可，不需要每节点一张活动干扰表。

更新必须覆盖所有 PHY 状态，包括本机 TX 期间和未锁定的外来帧；先用旧 strongRxEnd 判碰撞，再纳入新信号，避免与自己相撞。采用 `[start,end)` 边界，刚好衔接不碰撞；结束时间基于实际到达时刻，时长尚在计算中时也不能把该信号视作不存在。此项依赖 T02 的结果归属正确。

当前 RX 分支在 perValidWire 当拍禁止新增碰撞，CRC 又读旧 collideReg。必须按真实空口区间判断边界新帧是否重叠，将同拍条件直接纳入本次决定；不能把“查表返回当拍”直接当物理帧尾。

**验收：** A/B/C 中 C 失败；单帧成功；首尾刚好衔接成功；强帧在本机 TX 时到达后的尾部仍有效；弱隐藏帧不误标强碰撞；CRC 决策边界覆盖前/同/后拍。

### P02：接收完成、查表、概率与交付的一致性

当前 PHY 在 SYNC 和 RX 阶段都请求成功率表，syncCrcReg 是短脉冲，最终 CRC 没有使用它；noiseSum/currentmax/cycleCount 的清理由受状态 guard 限制的规则完成，rxEnd 在返回 IDLE 时置位，需要检查帧尾清理是否确实执行。CRC 成功到 lowMacRxReqQ 也通过一拍 crcReg，有背压时可能漏交付。

**最小修改方案：** 先明确 mode0 是每个完整包的一次最终成功/失败判决，保留表格式和强碰撞否决，定义 SYNC 查表目前承担的控制作用；需要保存的阶段结果保持到消费。按照帧开始/阶段结束/帧结束显式复位必要累积状态，保证干扰不会无意带入下一包。成功结果若未交付 MAC，用已有队列或一个 pending 保存，不能仅靠一拍 pulse。

PER 表实际上存成功阈值，16-bit perOut 与 16-bit 随机值比较；0/0xffff 的极值及 `>=` 的边界需实测确认，注释不要继续混用“丢包概率”与“成功概率”。保留现有编码，更新前先明确生产表对应的包长/校准条件。表索引只有 MCS/SINR，没有包长维度，不能宣称所有长度的整包概率都与 ns-3 相同。当前有效表区为 8×1120=8960 项；BRAM 容量、地址上界和动态配置测试的表达式需统一校验。

**验收：** 连续两个不同干扰条件的包互不污染；理想表、失败表及统计表符合声明；每次接收有界结束，成功包在有限背压解除后恰好交付一次。继续采用整包判决，不增加分段 BER 模型。

### P03：功率、拓扑和比较模型的边界

Types 的功率注释仍有 ×256，与当前 Q5/×32 用法不一致；实际 PHY 门限 128 对应 4 dBm，旧拓扑 power=2000 时 d=1023 的字段约 74，d=682 约 186。隐藏关系要基于实际路损表/返回功率验证，不能只看“距离很大”。PowerDb 为 12-bit 有符号，正负值读回、减路损及溢出范围也要验证。

CCA/SYNC/碰撞当前共用一个门限，是 mode0 的简化。先保留这个规则，用直接 PHY 测试确认外围相互不触发 CCA/SYNC，中心到外围的 CTS/ACK 能听到。仅有 ping 不通不能证明对方能量也不会触发退避。控制帧功率取 lasthighMacTxReq，接收专用中心可能使用默认或旧值，也须测量四类帧实际功率，避免把它当成天然对称链路。

本机 ns-3 InterferenceHelper 按干扰变化区间组合成功率；关闭 capture 不代表任意功率、任意短重叠都必然双败。保留 mode0 后可以要求协议行为、边界和受控条件一致，不能保证历史吞吐曲线逐点相同。多弱信号能量累加及 capture 不纳入本轮最小修改。

## 8. 自动化验证与通过门槛

### V01：先恢复有效回归，再扩展确定性场景

当前 test/Makefile 默认只运行 TestTop_per_cfg，不是全测试套件。此前实际编译发现 TestNode 引用缺失 PhyCoreSim、TestMac 的 PhyStatus 字段不完整、TestTop_new 将 Get 接口直接当状态传递。先选定有效入口，不把旧测试“正常退出”当回归通过。

优先复用 TestP2P、TestTop_cfg、TestTop_axil_ite、TestBsvTop_collision_v2、TestBsvTop_hidden_v2；死锁夹具迁入正常 test 目录并去掉对历史快照的固定依赖。每个测试使用独立构建目录，记录 HEAD、源码/表指纹、cycles/µs、BSC 版本、宏和完整命令。

| 回归组 | 必测条件 | 自动通过条件 |
| --- | --- | --- |
| 活性 | 三个已复现死锁、边界读取、持续读取、FIFO 堵塞/释放 | 有界进展，事件数守恒，无残留永久等待 |
| 时基 | tick、slot、IFS、MCS0—7 空口时长 | 周期与公式一致，固定流水偏移可解释 |
| 配置 | 16 节点、分组边界、非默认 IFS/CW、动态距离/PER | 读回及实际行为一致，配置不丢不串 |
| MAC | RTS off/on、错误响应、无响应、连续旁听、重试耗尽 | 类型/对端/ID 匹配，有限重试，一次完成 |
| PHY | 单帧、SYNC/RX 重叠、三帧尾部、首尾衔接、CRC 边界、TX 中外来帧 | 符合已声明 mode0 规则，无错归属/跨帧污染 |
| 桥接 | 各目标队列满、主机接收暂停、多源同时广播 | 释放背压后无静默丢重，字段完整 |
| 实现 | 新生成 Verilog、综合/布线、约束检查 | 无关键规则被永久阻塞；目标时钟 setup/hold 通过 |

必须有明确断言、失败状态及机器可识别的总结果。日志出现失败后不能再无条件打印 PASS；仿真器退出码和结果解析需要共同判断，watchdog 到期必须失败。原 collision_v2 只向 PHY 注入，不能替代完整 MAC/Channel/Arbiter 的碰撞回归。

hidden_v2 当前 lastSeq=0、首包 seq0 会漏计；`seq>lastSeq` 不是注释所称位图；接收计数没有完整按 PH_RUN 限定，计数重置/冷却与 RTS 切换可能混入前阶段。它只覆盖节点 0—7，每源固定周期发送也不证明饱和。修改测试时按完整 `(轮次,src,包ID)` 去重，区分重复与乱序，先排空再重置计数，完整覆盖最多 16 节点。

测试源与自动化脚本提交；原始日志、CSV/JSON、波形、构建产物放独立结果目录并忽略。RealEmu 可继续使用已忽略的 `output/<批次>/`，driver 使用 `tests/results/<批次>/`，不得再写用户目录或 scripts 下混入源码。

### V02：上板验证与 ns-3 对照

**上板顺序：** 配置应用验证 → 单包及连续 DMA/背压 → 单发送者 → 两发送者 → N=4 → N=8/15。N 为外围发送者，中心另算 1 个节点。每级均检查负载前后连通性、逐节点交付和排空，失败保留当批数据并停止扩大规模。

死锁验收不能只看总吞吐。所有发送者都要有进展；停止注入并允许完成有限重试后，队列能排空；MAC 等待/PHY 空闲/计时未启动不能持续。修复寄存器抢拍后才把运行中轮询监控作为稳定性测试的一部分，避免监控本身改变原系统。

建议每个 N×RTS 条件至少 10 次独立运行，记录随机初始条件、负载、窗口与结果分布；长稳测试在有限批次间验证恢复，不能用重启清空失败后继续累计成一轮 PASS。板卡运行依赖停止条件和资源清理，沿用现有已审查的测试入口。

| 对照项 | 必须固定/记录的内容 |
| --- | --- |
| 版本 | RealEmu/driver/ns-3 提交、源码和表指纹、Verilog/bitstream SHA、实际加载记录 |
| 时钟 | Vivado user_clk、cycles/µs、实现时序通过报告；板上加载版本可追溯 |
| 帧 | UDP payload、实际 PSDU 长度、MAC/LLC/IP/UDP/FCS 口径，不把 1000B 直接当空口帧长 |
| 速率 | 802.11a 20 MHz，数据索引7=54M；RTS/CTS/ACK 实际 6M，ns-3 以 trace 验证 basic rate 选择 |
| 竞争 | 实际 CWmin/CWmax、指数编码转换、slot/IFS、NAV、重试总次数、timeout 事件语义 |
| 拓扑 | 中心双向可达、外围互不可感知；路损/功率/CCA/SYNC 条件均验证 |
| 流量 | 每源请求负载与实际接受负载、队列深度/占用/软件限流，不能以请求100M证明饱和 |
| 统计 | 相同预热/测量/排空，唯一 payload goodput、发送包群未交付率、重复/乱序、逐源公平性 |
| 模型 | 理想成功率表的协议比较与生产表概率比较分别报告；mode0 剩余差异明确 |

历史 M0 受控参考代码仍保存在备份中，不是当前仓库已有测试入口；恢复时单独审查，并以本机固定 ns-3 提交重建。ACK/CTS 速率不能只看 ControlMode 配置，basic rate set 也会影响实际应答选择。

通过门槛分三级：一级为确定性功能断言全部通过、无死锁；二级为配置/时钟/拓扑/统计口径一致且全源有进展；三级才评估吞吐分布与 ns-3 的偏差。数值容差先由重复实验的波动和可接受模型差异确定，不能预设一个百分比后通过调 CW/timeout 拟合历史曲线。
