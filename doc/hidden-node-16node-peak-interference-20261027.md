# 16 节点隐藏节点：差异原因、整包最大干扰模型与仿真验证

最终结果：当前源码的48次回归全部通过，30次受控隐藏节点实验均完成100ms测量及停止发流后的队列排空。16总节点、15隐藏发送者下，RTS off为RealEmu 2.88 / ns-3 3.20Mbps（-10.00%），RTS on为12.24 / 12.28Mbps（-0.33%）；十个对照点中九个相差不足4%。详细口径、范围及限制见第8节。

本次分支为 `hidden-node-16node-20261026-wcl-sim`，修改前提交为 `e0f302f3beef91aad70dd332ee3b0c28337e9995`。本文区分源码问题、测试场景差异和概率模型近似；不把功能测试通过等同于完整复现旧 ns-3 曲线。当前修改尚未提交，也没有生成或烧写新固件。

## 1. 原来主要为什么不一致

最直接的原因是：原隐藏节点测试没有提供与参考实验一致的输入；PHY 没有正确维护干扰信号的生命周期；MAC 的退避、应答和状态查询还有影响多节点行为的问题。这些因素同时存在，不能把全部差距都归因于一个 PER 公式。

| 位置 | 修改前的实际逻辑 | 对隐藏节点实验的影响 |
| --- | --- | --- |
| `test/TestBsvTop_hidden_v2.bsv` | 测试节点数为 8，发送者为 1/2/4/7；核心虽然实例化 16 节点，测试没有驱动完整拓扑 | 不能据此声称完成 16 节点隐藏节点验证 |
| 同上，PER 初始化 | 全部条目写 `FFFF`，即成功率 100% | SINR 变化不再影响概率判决；主要测的是额外的强帧碰撞硬否决 |
| 同上，发包间隔 | 每源 1000 µs 一包，每包计 1000 B | 每源只有 8 Mbps；参考为每源 100 Mbps，尤其 N=1/2 没有相同的饱和负载 |
| 同上，发包相位 | 条件余数为节点编号 `n`，单位是周期 | 默认 250 cycles/µs 时相邻源相差 4 ns，并非注释中的 1 µs，业务形成周期性近同步突发 |
| 同上，MAC 参数 | CWmax 指数 7，即窗口最大值 127；帧长 1038 B | 与 CWmax=1023 的参考不一致；当前 PHY 下 1038 B@54M 为 176 µs，新的非 QoS 对照帧为 180 µs |
| 同上，RTS Duration | 描述符填 0，RTS 继承 0，CTS 也减成 0 | 旁听节点依靠旧 NAV 下限 119 µs；不足以覆盖 DATA/ACK 交换，RTS on 标签不代表保护范围正确 |
| 同上，统计 | `lastSeq` 初值 0，而首包 seq 也为 0；接收计数不限制在测量阶段 | 首次 seq=0 被当作重复；冷却期间收包可以计到下一档；换 RTS 时又没有完整排空边界 |
| 同上，结束条件 | 到时间打印吞吐再 `$finish`，没有充分的功能断言 | 正常结束不等于收发/应答/恢复正常 |
| `src/PhyCore.bsv` | 每 5 µs 取新到事件功率最大值，然后把各窗口最大值累加 | 既不是当前并发总干扰，也不是本包期间的最大总干扰；没有按干扰帧结束时间移除贡献 |
| 同上，PHY 准入 | 没有锁定的后到帧，其剩余生命周期未独立维护 | A/B 碰撞后，B 的尾部可能没有影响随后才开始的 C，使高负载下接收过于乐观 |
| 同上，碰撞判决 | `!collideReg` 是成功的必需条件 | 任意过门限的重叠都硬失败；即使目标远强于干扰、概率表本应允许成功，也无法通过 |
| `src/CsmaUtils.bsv` | 各节点 LFSR 使用同一种子，节点差别只混入少数低位 | 同步抽样时，相差 4 的节点产生完全相同的退避流；隐藏节点无法相互退让，重复同组碰撞 |
| 同上，普通 CW 更新 | `incrCW/resetCW` 不清理已经预取的样本 | 下一次竞争可能仍使用旧窗口生成的随机退避 |
| `src/MacCore.bsv` | 冻结后直接恢复扣 slot | 缺少重新等待连续空闲 DIFS/EIFS 的过程 |
| 同上，包级/站级重试 | MPDU耗尽重试就resetCW，将两种计数合并 | 当前ns-3的站级失败计数跨包保留；饱和隐藏节点下，过早回到CWmin会增加碰撞 |
| 同上，应答等待 | 固定计时等待完整 ACK/CTS，没有接收开始后的延长语义 | 直接将参考的约 45 µs 写入旧寄存器会把正常的 6M ACK/CTS 当成超时；保留 300 µs 又会改变碰撞后的等待成本 |
| 同上，寄存器访问 | 查询和配置写共用一个会调用配置消费者的规则 | BSC 会将查询也与 MAC/CSMA 状态机互斥；持续轮询可阻止启动或吞掉退避 slot 脉冲，造成卡住 |
| 同上，即时应答 | SIFS倒计时仍受CCA/NAV阻挡，PHY也要求等新接收完成才发送ACK/CTS | 后到RTS可把应答推迟到发送者已超时之后；定向测试复现晚约57µs |
| PHY/Arbiter时间线 | 接收端把元数据到达周期当成空口开始周期，仲裁只按节点编号选择 | 不同传递延迟会把首尾相接的发送伪造成重叠，整包峰值模型对此尤其敏感 |
| 退避slot相位 | 使用自由运行的全局slot脉冲扣数 | 一个slot可能只等待0–9µs中的任意部分，各节点还被锁在共同的9µs相位上；新增测试实测旧代码只等201周期，即250时基下约0.804µs |

旧 `hidden_v2_build.log` 的时间为 2026-10-22，不能作为本次提交后源码的实测。其 N=1/off 曾出现 raw=20、unique=19，也符合首包 seq=0 被错误去重的问题。

此前 driver 的 `-A` 已做过 CWmax、帧长和预约等上层调整；这些设置不会自动作用于独立的旧 BSV 测试。不能继续把“最新板测仍使用默认 CWmax=63”当作已知事实。

## 2. 隐藏拓扑还需要校准什么

隐藏节点必须满足两个条件：外围节点之间不能独立建立接收/载波侦听；它们的发送仍然会在共同接收端形成干扰。不能把“低于 CCA 门限”解释成“功率为零”。

当前默认距离表中，d=8 的损耗为 578，d=1023 为 1926，单位为 1/32 dB。发送功率字段 2000 时，目标接收功率为 1422，外围相互接收功率为 74：

- 两类链路相差 **42.125 dB**，参考的 -40/-110 dBm 则相差 **70 dB**；统一加减一个功率偏置无法修正这个差值。
- 当前噪声为线性 256，相当于内部 0 dB。查 `Lg.mem`，功率 74 对应线性 436，即单个隐藏信号仍比噪声高约 **2.312 dB**。
- 14 个这样的隐藏信号加噪声，比单独噪声高约 **13.952 dB**。多节点时是否累加会明显改变结果。
- 旧 BSV 测试不给中心节点下发自身 DATA。中心控制帧功率取 `lasthighMacTxReq` 的默认值 992，与外围 DATA=2000 差 **31.5 dB**。这也是旧测试的额外不对称，不能假定与最新板测的初始化状态相同。

数值核算保存在 `output/hidden-node-analysis-20261026/source-audit-numbers.json`。这些是默认距离模型的内部单位，不应直接当成真实 RSS=-40/-110 dBm。

本次使用显式固定 RSS 的测试适配器排除这些输入差异，保留生产 MAC、PHY 和 Arbiter。没有全局改写 `20lgd.mem`，也没有借此声称默认距离模型已经校准完毕。

## 3. 本次实现的简化算法

对目标包 A 的完整 PPDU 区间 `[t_start,t_end)`，定义：

```text
I(t)    = 同一时刻仍在空口的其他信号的线性功率之和
I_peak  = max I(t)，t 属于 A 的完整存续区间
SINR_A  = P_A / (Noise + I_peak)
PRR_A   = 原来的整包成功率表(MCS_A, SINR_A)
PER_A   = 1 - PRR_A
```

这里的“最大干扰”是**最大并发总干扰**。两个同时存在的弱干扰要相加；两个先后出现且不重叠的干扰不能跨时间相加。所有功率先转为线性单位，不能相加 dB。

保留 mode0 的整包方式：最终只进行一次整包随机成功/失败判决，没有增加分段 BER。为隐藏查表延迟，可以提前查表；如果末尾来了更强干扰，则重新查表，最终只采用与最终峰值相符的结果。

实现集中在 `src/PhyCore.bsv`：

1. 每个源保存最近一帧的原始到达时间、结束时间和线性功率。区间记录在 IDLE、SYNC、RX、TX 都继续更新；没有锁定的帧也有完整生命周期。
2. 一个源同一时间只有一个合法空口发送，因此 16 个有界源记录即可，不增加通用事务表。
3. 并发总功率只会在新信号开始时增加；结束只会降低总功率。因此在目标包开始、以及后续每个信号的开始点计算并发功率和，即可取得精确的区间峰值，无需每周期积分。
4. 计算采用事件的原始时间，而非 ROM/除法返回时刻；将功率与时长按同一事件次序配对，避免尾部干扰被流水延迟漏掉。
5. 当前目标源/帧从干扰中排除，噪声仅加入一次。总和使用 36 位，进入原 32 位对数查找器前饱和，防止相加回绕。
6. 查表请求携带噪声快照。接收结束时必须确认所有在途能量元数据已处理，且成功率结果对应最终峰值。
7. `collideReg` 保留作重叠诊断，取消其无条件失败的作用；成功率为 0 的条目也显式禁止成功。
8. 每个包重新初始化峰值；过期记录在保留足够流水历史后清掉 valid，避免 32 位周期计数绕回时让沉默节点的旧干扰复活。回收请求保持到可执行周期。

内部 `PhyEvent` 还携带原始空口开始周期和有效位，TX原子提交时记录共同模型时钟；信道、仲裁和广播保留此值，接收端补偿已经经过的时间。没有时间标签的直接注入测试继续使用本地到达周期。

例如真实A为0–180µs、B为180–360µs。若A元数据晚到4µs、B晚到1µs，旧模型会得到A=4–184、B=181–361，凭空多出3µs重叠。最大干扰公式本身不能修复这种时间错误。新增测试将元数据延迟5µs，旧RX_END比TX_END晚1249周期，新模型仅有正常观察流水的1周期差。

`src/Arbitration.bsv` 在原两级树中优先选择更早的空口时间；相同时刻保留原高编号平局规则，未带标签的历史测试也保留原行为。16节点测量器对每个接收端额外检查时间标签非递减，乱序即判失败。

原始时间标签也要求半双工检查使用原始时刻：在本机TX期间开始的前导，不能因为元数据在TX_END之后才到就被补收。PHY只在结束后的一个前导窗口内保留本机TX_END历史，拒绝这类补收；恰在TX_END开始的帧仍可接收。能量记录继续维护，因此不能解码的帧仍可干扰后续目标。

例如 A 为 0–180 µs，B 为 100–280 µs，C 为 200–380 µs。A 与 B 碰撞后，即使接收机没有锁定 B，C 的前 80 µs 仍必须受到 B 干扰。本实现会保留这段尾部。

| 文件 | 修改及原因 |

| `src/CsmaUtils.bsv` | 新增5位站级失败计数，按当前ns-3的Txop语义跨MPDU保留；普通增大/复位窗口清理旧预取；各节点使用不同非零种子，可用 `REALEMU_BACKOFF_SEED` 重复编译试验 |

| 同上 | 应答接收已开始时延长到接收结束；完成后保留 0.4 µs+8 周期给原交付流水。超时默认值未全局改成 45，测试显式配置 45 |
| 同上 | 纯读寄存器独立规则，配置写保持原校验和传播路径，使查询不再阻挡协议进度 |
| MAC/PHY | SIFS应答不重新竞争CCA/NAV；已提交的ACK/CTS可中止SIFS期间新开始的RX。普通RTS/DATA仍保持D01的忙时排队语义 |
| PHY | 若RX物理时间已结束、成功事件只因输出FIFO满而等待交付，则先保留并交付事件，不能被即时TX抢占丢弃；三包填满输出并追加ACK的测试验证此边界 |

持续查询问题有独立证据：CSR 拆分前的 16 节点回放中，cycle 从 650000 前进到 660000（50 cycles/µs），节点 1 的剩余退避仍为 498；另一个节点处于 DCF 等待退避但 CSMA_IDLE。拆分后的定向测试要求在**查询始终持续**的情况下完成发送、无 ACK 超时和队列排空，不允许靠停止轮询才恢复。

本次保持主机 `MacEvent`、DMA 数据格式和完成接口不变；内部 `PhyEvent` 新增33位空口时间信息。`HIDDEN_SOURCE`的completed是收到的上层TX完成响应数，并不包含全部无应答丢弃；排空依据真实DCF状态和FIFO计数。接收去重仍由本次测量器执行；原MAC向上层上报重复DATA，以及RX成功与TX ACK完成的接口区别，不能因此认为已经一起修好。

SIFS应答的依据可核对本机ns-3：`FrameExchangeManager::DoSendCtsAfterRts/SendNormalAck` 直接发送应答，`WifiPhy::Send` 允许在正在同步接收时转入TX。新增ACK/CTS用例先收到一个好帧，再在其结束5µs后送入另一RTS；旧回复分别约252.6/124.6µs，新回复约195.6/67.6µs，对应目标196/68µs。输出背压例外保留原C02的数据可靠性。

旧 driver 的 `ns3-11a-legacy-cts64` 描述符额外加了 4 µs 补偿旧 CTS 扣减。以后用本次 RTL 生成固件时应移除该兼容项；当前板卡未换本次固件，因此没有擅自修改正在使用的 driver 配置。

### 跨包CW差异的直接证据

本机ns-3的 `FrameExchangeManager::NormalAckTimeout` 先按MPDU重试计数决定是否丢包，随后仍调用 `TransmissionFailed`，由 `Txop::UpdateFailedCw` 更新站级计数。`FrameRetryLimit=7` 时，失败后的窗口序列为31、63、127、255、511、1023、1023、15。第7次失败可以丢弃该MPDU，但不会立即把站级CW变回15。

`output/hidden-cw-20261027-ns3-audit/run1.log` 实际记录节点1的CW变化：0µs为15，295µs为31，734µs为63，1011µs为127，1495µs为255，3536µs为511，3876µs为1023，13055µs仍为1023，20622µs才回到15。这是运行轨迹，不只是在解释源码。

修正前的中间版本在N=15、RTS off的100ms窗口中，三种Real种子的DATA发送尝试为958/992/969次；ns-3对照的尝试次数明显更少。较频繁地恢复CWmin使隐藏节点更激进，最终吞吐中位数只有1.68Mbps，对照为3.20Mbps。不能在未检查站级CW前，把这47.5%的差距笼统归因于PHY峰值近似。

另一个观测程序 `--auditPhy=1` 在十次ns-3的同一条件下记录381次成功DATA，其中仅5次在前导码期间与其他强信号重叠，载荷重叠为0。因此短重叠的概率模型差异不是这轮大偏差的主要直接来源。观测不改变ns-3收发、误码率或调度。

新增 `TestCwFailureSequence.bsv` 对各档抽取128个退避样本，检查上界并要求出现高半区样本，验证跨包失败序列及成功复位。修改前HEAD在第8次失败时抽到593，而参考上界应为16，明确失败；当前修复通过。

## 5. 新的 16 节点对照场景

`test/TestHidden16.bsv` 实例化 16 组生产 MAC/PHY，通过生产 Arbiter 传递所有 RTS/CTS/DATA/ACK；0 为中心，1..N 为隐藏发送者，N 最大 15。固定 RSS 适配器替代距离信道，以便明确比较 MAC/PHY；DMA、配置桥和原距离信道另由既有回归覆盖。

| 参数 | RealEmu 与新 ns-3 对照的共同口径 |
| --- | --- |
| 总节点 / 发送者 | 16 / N=1、2、4、8、15；16 总节点不能冒充参考的 16 个发送者 |
| 帧及吞吐 | 非 QoS DATA PSDU=1064 B，固定计 1000 B 应用负载，接收时间窗口内统计唯一包 |
| ns-3 发包形式 | PacketSocket 携带 1028 B，模拟 1000 B 负载+28 B IP/UDP 开销；LLC8+MAC24+FCS4 后为 1064 B，trace 强制核验 |
| 标准 / 速率 | 802.11a 20MHz；DATA54M，RTS/CTS/ACK 全为6M，trace 强制核验 |
| 目标/隐藏 RSS | -40/-110 dBm；290K、NF7dB，归一化并量化为内部功率1727/-513，噪声256 |
| 退避 | CW15..1023，slot9、SIFS16、DIFS34、EIFS94 µs |
| 重试 / 应答 | Real retry6，即初传+最多6次重试；ns-3 FrameRetryLimit7；45 µs 等 RXSTART 后延长至 RXEND |
| 预约 | RTS316、CTS256、DATA60、ACK0 µs，对应 DATA180、CTS/ACK44、RTS52 µs |
| 业务 | 每源80 µs一包，相位错开1 µs，即每源100 Mbps；记录实际提交和收到的唯一包，不把背压后的接纳量当作原始 offered load |
| 队列 | 对照 ns-3 MAC 队列10；Real MAC 内队列10，另有原输入接口缓冲，不能宣称整个缓冲体系完全等价 |
| 窗口 | 默认预热2 ms+测量10 ms作功能检查；`+long` 为20 ms+100 ms统计窗口；独立进程隔离各条件，停止发流后还要求实际排空 |
| 时基 | 源码硬件默认仍为250 cycles/µs；`hidden16-fast` 仅把统计实验统一模型时基设为50，必须明确标注并交叉验证，不把它说成新的硬件频率 |

原 PHY 已包含 22 bit SERVICE/tail，本次没有再次人为增加字节补偿。1064 B 非 QoS 对照帧与前次 driver 的1066 B QoS帧都处于180 µs的OFDM时长档位，但协议头口径仍应分别标明。

ns-3 对照程序为 `test/ns3-hidden-reference.cc`，使用本机 `/home/gtx/dev/ns-3-dev-git` 的库，不修改其源码。设置 `ConstantRate::ControlMode` 只会约束 RTS，因此还显式配置 supported/basic modes，并核查实际全部控制帧速率，防止 ACK 自动选成更高速率。

它是新增的受控参考，**不等同于恢复了旧 Case2 的完整实验**。本机保存了旧汇总 CSV，但其列出的 `hidden-terminal.cc` 原始复现文件缺失；旧 AP/STA、队列100、控制速率等细节没有全部核实。本次没有拿 N=15 的结果与旧 N=16 点计算误差。

## 7. 一致性的边界

本机ns-3的 `src/wifi/model/interference-helper.cc::CalculatePayloadPer` 按干扰变化划分时间段，用对应SINR、持续时间和调制计算段成功率，再组合成包成功率。本文结论以本次构建的本机源码版本为准。

本次整包峰值方法把最坏瞬间应用到整包，保持了用户要求的简单 mode0。它一般比考虑重叠持续时间的方法更保守；例如同样峰值、但仅重叠1 µs和重叠100 µs，会得到相同的本模型成功率，ns-3通常不同。不能承诺任意功率、包长和碰撞时间下都与ns-3逐包相同。

每次接收开始时锁存一次随机数，最终成功决定在输出背压期间保持不变。50% PRR的双PHY对照中，立即消费与延迟消费得到完全相同的48包成功掩码；旧代码会在FIFO满时重新取样，导致结果受上层读取速度影响。

当前表只按 MCS/SINR 索引，没有运行时包长维度；原始曲线标定长度也未由表本身提供。固定1064B场景的接近，不证明短控制帧与所有数据包长的概率都校准完成。未增加 capture/分段BER，也没有为了贴合旧曲线而乘吞吐系数。

还有一个既有的状态显示问题：`mac_backoff_state_off`仍读取未更新的`macStaReg.backOffState`缓存，不能凭该寄存器的0认定CSMA真实空闲。本次排空使用真实`dcfStateReg`和FIFO计数，持续查询定向测试也要求实际发送和超时恢复；状态显示修正未纳入本轮吞吐对齐改动。

新能量记录和加法路径改变了 RTL。本次仿真通过后仍须重新完成250MHz实现时序验收，才能把既有固件的时序结论用于本次修改；此前2ps裕量不适用于新实现。本轮不把旧 bitstream 当作已包含这些修改。

最终实验数值见第8节；原始日志、源码校验值和对比CSV均保存在 `output/`。
